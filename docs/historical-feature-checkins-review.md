# 古都内部遗迹独立打卡核验

## 原问题

ClassicalSites的内部要素详情复用所属古城／世界遗产按钮，因此宫殿详情中的取消打卡可能取消整个关联世界遗产。内部几何没有独立访问状态。历史打卡匹配还按名称、坐标和城市别名推断身份，不适用于独立内部要素。

## 当前规则

- 古都根点、内部遗迹、世界遗产分别记录；内部遗迹不自动标记父城、世界遗产或其他内部要素。原有明确共享身份的古都／世界遗产关联保留。
- ClassicalSites、PompeiiSites和AncientCapitalWalls复用全局遗迹打卡处理。北京、洛阳演变模块目前输出古都根点，继续使用根点逻辑，不再建立一份独立根点打卡。
- 独立遗迹以提供方和原始要素标识关联。少数在线图层没有标识的要素采用来源、名称与原始几何的确定性指纹，不用名称或相同坐标直接合并。复制到标签锚点时保留同一标识。
- 打卡存入现有地点及访问记录，保存historicalFeatureId、提供方和父城参照。父城参照仅表达归属关系，不参与打卡状态推断。现有存档格式兼容，不创建独立图层、开关或legend。
- 已打卡要素标签增加勾号，轮廓加粗；保持朝代色彩、原始几何和孔洞。取消打卡恢复原样。开放多线仍开放，闭合面仍按其真实对象填充。
- 根点、里坊格网及纯研究参照线不作为单独景点。不可证实的唐长安研究参照点也不生成景点打卡。现存地标与实际遗迹仍可单独记录。
- 同名、同坐标的不同要素互不影响。取消遗迹仅取消精确标识对应的访问；取消父城／世界遗产不会删除独立遗迹访问。连续点击同一个待完成按钮不会反转旧状态。
- 内部几何可见时隐藏其重复通用打卡点；缩放过小或关闭古都／城郭时，通用打卡点继续遵循“我的打卡”开关显示。
- 内部详情按钮明确写“打卡此遗迹／取消此遗迹打卡”。根点保留原古城／世界遗产操作；修正部分根点缺少checkinItem时详情操作传入空条目的问题。

旧打卡保留原有身份，不根据过去的城市或世界遗产打卡猜测宫殿已经到访，也不自动把旧记录拆分成多个新记录。研究数据不因打卡变化而写回。

## 验证

新增测试覆盖同名同坐标不同要素、父子取消隔离、不可变几何、快速重复操作、根点不重复登记及Leaflet样式。完整现有回归零失败，相关JavaScript语法和git diff --check通过。

独立临时浏览器实际操作日惹王宫：内部按钮不再包含父遗产打卡按钮；打卡宫殿不改变古都及世界遗产，取消宫殿保留古都，取消古都保留宫殿。重载后稳定要素身份及访问记录保留，中文／英文显示通过。等待实际渲染的标签状态完成后保存截图。

另实际打卡及取消庞贝阿波罗神庙和中国宫殿要素，提供方状态独立变化，无页面脚本错误。截图及结果位于output/historical-feature-checkins，未使用用户真实浏览器存档。
